# Bugbot — правила ревью TG_parser

Bugbot не читает `.cursor/rules/`. Нормы ниже — выжимка из `AGENTS.md`, `.claude/agents/code-reviewer.md` («Рискованные изменения») и accepted ADR. Полный контекст — в этих файлах.

## Считать дефектом

- **Авторизация fail-open.** Любая ветка bot / MCP / API, где при ошибке резолва identity, отсутствии пользователя или исключении доступ разрешается, а не запрещается. Пропущенная ownership- или RBAC-проверка на одной из симметричных поверхностей (bot / MCP / API, read / write) — класс BUG-093 / BUG-099 / BUG-101.
- **Значения в логах.** Логировать можно имена ключей, но никогда значения: токены, API-ключи, тексты сообщений пользователей, содержимое `.env` (BUG-087 / BUG-088).
- **Confirm-gated write-инструменты** (удаление канала, смена LLM-конфига и т. п.), которые можно выполнить без подтверждения или с подтверждением, полученным не детерминированно (ADR 0020).
- **Нарушение JSON Schema** в `docs/contracts/**` или решения accepted ADR в `docs/adr/`.
- **Alembic-миграции**: необратимые без явного обоснования, расходящиеся с моделями, без downgrade.
- **Стоимость LLM**: новый или расширенный вызов модели в цикле, на каждом тике планировщика или без лимита; рост контекста Phase 2 discover (BUG-108).
- **Compose / env**: новая настройка, которую читает воркер `tg_parser`, но которой нет в `environment:` сервиса (класс BUG-092) и в `SCHEDULER_CRITICAL_ENV`.
- **`.gitignore`**, после правки которого в git может попасть `.env`, `*.session`, `.cursor/mcp.json`, `.claude/settings.local.json`.
- **Тесты**, которые прошли бы и без исправления; новые `skip` / `xfail` без обоснования.

## Не считать дефектом

- Стиль и форматирование — их проверяет `ruff` в CI.
- Файлы в `docs/notes/**` — журнал сессий, а не нормативная документация.
