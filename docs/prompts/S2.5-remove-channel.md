# S2.5 — `remove_channel` MCP Tool + Cascade Repo Methods

## Goal

Add a `remove_channel` MCP tool that fully removes a Telegram channel and **all** its
data from the system. This completes the channel CRUD lifecycle
(add / pause / resume / **remove**).

---

## 1. Scope of Deletion (3 databases, 10 tables)

Data is spread across **three separate PostgreSQL databases** (no cross-DB
transactions). The system must delete in the correct order due to one FK
constraint and must be idempotent in case of partial failure.

### 1a. Processing DB (`processing_storage_session`)

| # | Table | Filter | FK constraint | Priority |
|---|-------|--------|---------------|----------|
| 1 | `document_embeddings` | subquery on `processed_documents.channel_id` | `source_ref → processed_documents(source_ref)` **no CASCADE** | **FIRST** (FK child) |
| 2 | `processed_documents` | `channel_id = :channel_id` | FK parent of embeddings | after embeddings |
| 3 | `processing_failures` | `channel_id = :channel_id` | none | any order |
| 4 | `topic_cards` | JSON LIKE `sources_json` | none | any order (method exists) |
| 5 | `topic_bundles` | JSON LIKE `channels_json` | none | any order (method exists) |

**Optional** (low-value, not blocking; skip in v1):

| # | Table | Filter |
|---|-------|--------|
| 6 | `api_jobs` | `channel_id = :channel_id` |
| 7 | `task_history` | `channel_id = :channel_id` |

### 1b. Raw DB (`raw_storage_session`)

| # | Table | Filter | Notes |
|---|-------|--------|-------|
| 8 | `raw_conflicts` | subquery on `raw_messages.channel_id` | delete before `raw_messages` (logical ref) |
| 9 | `raw_messages` | `channel_id = :channel_id` | |

### 1c. Ingestion DB (`ingestion_state_session`)

| # | Table | Filter | Notes |
|---|-------|--------|-------|
| 10 | `source_attempts` | `source_id = :source_id` | |
| 11 | `comment_cursors` | `source_id = :source_id` | |
| 12 | `sources` | `source_id = :source_id` | **LAST** in ingestion DB |

---

## 2. Required Delete Order

```
Processing DB (single session, single transaction):
  1. document_embeddings  (FK child)
  2. processed_documents
  3. processing_failures
  4. topic_cards          (reuse existing delete_by_channel)
  5. topic_bundles        (reuse existing delete_by_channel)

Raw DB (single session, single transaction):
  6. raw_conflicts        (references raw_messages.source_ref)
  7. raw_messages

Ingestion DB (single session, single transaction):
  8. source_attempts
  9. comment_cursors
 10. sources
```

Each DB group is one transaction. If a later group fails, the
earlier deletions are already committed — the operation is designed to be
**idempotent** (re-running skips already-deleted rows).

### Step 2: SQLAlchemy implementations

#### `SAIngestionStateRepo.delete_source(source_id)`
```sql
DELETE FROM source_attempts WHERE source_id = :source_id;
DELETE FROM comment_cursors WHERE source_id = :source_id;
DELETE FROM sources WHERE source_id = :source_id;
-- commit
```
Return `True` if sources DELETE affected > 0 rows.

#### `SARawMessageRepo.delete_by_channel(channel_id)`
```sql
DELETE FROM raw_conflicts
WHERE source_ref IN (
    SELECT source_ref FROM raw_messages WHERE channel_id = :channel_id
);
DELETE FROM raw_messages WHERE channel_id = :channel_id;
-- commit
```
Return rowcount from the second DELETE.

#### `SAProcessedDocumentRepo.delete_by_channel(channel_id)`
```sql
DELETE FROM processed_documents WHERE channel_id = :channel_id;
-- commit
```

#### `SAProcessingFailureRepo.delete_by_channel(channel_id)`
```sql
DELETE FROM processing_failures WHERE channel_id = :channel_id;
-- commit
```

#### `SAEmbeddingRepo.delete_by_channel(channel_id)`
```sql
DELETE FROM document_embeddings
WHERE source_ref IN (
    SELECT source_ref FROM processed_documents WHERE channel_id = :channel_id
);
-- commit
```
Return rowcount.

### Step 3: New context manager in `db_context.py`

```python
@asynccontextmanager
async def removal_repos():
    """Context manager for channel removal (all three DB sessions)."""
    db = Database.from_settings(settings)
    try:
        await db.init()
        state_session = db.ingestion_state_session()
        raw_session = db.raw_storage_session()
        proc_session = db.processing_storage_session()
        try:
            yield (
                SAIngestionStateRepo(state_session),
                SARawMessageRepo(raw_session),
                SAProcessedDocumentRepo(proc_session),
                SAProcessingFailureRepo(proc_session),
                SAEmbeddingRepo(proc_session),
                SATopicCardRepo(proc_session),
                SATopicBundleRepo(proc_session),
                db,
            )
        finally:
            await state_session.close()
            await raw_session.close()
            await proc_session.close()
    finally:
        await db.close()
```

### Step 4: MCP tool in `mcp_server.py`

#### Pydantic schema:
```python
class RemoveChannelResult(BaseModel):
    channel_id: str
    removed: bool
    message: str
    details: dict[str, int]   # table -> deleted_count
```

#### Tool:
```python
@mcp.tool()
async def remove_channel(
    channel_id: str,
    confirm: bool = False,
) -> RemoveChannelResult:
    """Permanently remove a channel and ALL its data from the knowledge base.
    This action is IRREVERSIBLE. Set confirm=true to proceed.
    Removes: source config, raw messages, processed documents, embeddings,
    topics, and processing failures.

    Args:
        channel_id: Channel ID (with or without @).
        confirm: Safety flag — must be true to actually delete."""
```

**Logic:**
1. Normalize `channel_id`.
2. If `confirm is False` → return `removed=False`, message explaining the
   safety requirement.
3. Check running pipelines (`_running_pipelines`) — refuse if pipeline is active.
4. Open `removal_repos()`.
5. Verify source exists (`state_repo.get_source`). If not, return `removed=False`.
6. Delete in order (processing DB → raw DB → ingestion DB), collect counts.
7. Return `RemoveChannelResult` with all counts.

## 5. Acceptance Criteria

1. `remove_channel("my_channel", confirm=True)` deletes all 10 tables' data for that channel.
2. `remove_channel("my_channel", confirm=False)` returns a warning, deletes nothing.
3. `remove_channel("my_channel")` while pipeline is running → refuse.
4. All new port methods have abstract definitions + SA implementations.
5. `removal_repos()` context manager works correctly.
6. Existing tests pass (0 regressions except pre-existing `TestListTopicsTool` failures).
7. New tests cover the MCP tool + each repo delete method.
8. `INSTRUCTIONS.md` updated.
