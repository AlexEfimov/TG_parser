## 2. Scope

**Входит:**

1. **MCP `get_topic_details`** — элементы порциями:
   - необязательные аргументы смещения и размера порции; имена — §3 п. 2 (рекомендация — `offset` / `limit`, как у остальных read-инструментов: тогда `build_pagination_pending` работает без изменений);
   - **новые поля** ответа: `items_count` (полное число) и признак продолжения; `pagination_pending` — только когда продолжение есть, с сохранением `topic_id` и `workspace_id`, чтобы повторный вызов прошёл ту же проверку workspace;
   - сортировка при выдаче ключом TR-63 — вынести ключ в один helper и переиспользовать (по возможности — и в трёх местах записи);
   - бандла нет → `items=None`, `items_count=0`, признак продолжения `false`, без `pagination_pending`; смещение за пределом → пустой список, не `None`;
   - остальные поля `TopicDetail` не меняются; клиент без новых аргументов получает первую порцию и `items_count`;
   - docstring описывает пагинацию так, чтобы агент понял, как получить следующую порцию; формулировка Q4 R3 — без смены семантики.
2. **MCP-ресурс `tgparser://topics/{topic_id}`** — поведение по §3 п. 3 (рекомендация — первая порция плюс `items_count` и признак продолжения, это записано в docstring ресурса).
3. **HTTP `GET /topics/{id}/bundle`** — query-параметры смещения и размера, сортировка, `total_items` как сейчас плюс признак продолжения. Превышение верхней границы — по §3 п. 5. Значения по умолчанию — общая для MCP и HTTP константа в коде; переносить её в настройку `.env` — только решением §3 п. 1.
4. **Бот `get_topic_details`** — убрать сериализацию всех элементов (`items_count = len(bundle.items)`), формат ответа не меняется; описание инструмента не должно обещать элементы бандла.
5. **Документы** — все из списка §1 и `CHANGELOG.md` (в том числе строка про смену `inputSchema` / `outputSchema`: клиентам, кэширующим список инструментов, например коннектору ChatGPT, может понадобиться обновить его, чтобы увидеть новые аргументы).
6. **Протокол деплоя** — `docs/runbooks/BUG109A_R19_DEPLOY.md` (по образцу `BUG107_R14_DEPLOY.md`).

**По решению §3 п. 4, не входит по умолчанию:** проверка доступа в `/bundle` при отсутствии карточки и форма ответа (403 или 404).

**Не входит:**

## 4. Ловушки

- **`pagination_pending` и имена аргументов** (§1): подсказка должна повторяться как есть. Тест — повторный вызов строго по подсказке.
- **Аддитивность.** `items` остаётся тем же полем того же типа. Тесты, ждущие все элементы в `items`, переписать под новый контракт, а не удалять. `test_f4b_scoping_read_tools.py` (`full_bundle_equals_null_workspace`) должен остаться зелёным без правки семантики: сравнение набора с `workspace_id` и без — на одинаковой порции.
- **Сортировка — при выдаче**, ключом TR-63: прямой `upsert` порядок не гарантирует. `score` равны у многих элементов (например, 0.111), поэтому тай-брейк по `source_ref` обязателен для стабильных страниц.
- **`None` ≠ пустая страница.** `items=None` значит «бандла нет», за пределом — `[]`.
- **RBAC до пагинации**, как сейчас; пагинация не открывает путь к чужой теме. Матрицы BUG-100 / BUG-107 зелёные.
- **Верхняя граница — на сервере**, а не в описании.
- **Бот:** не добавлять `pagination_pending` в ответ бота (`bot/agent.py:486`).
- **Ресурс** — тот же код, но без аргументов: не оставить его молча «первой порцией» без признака продолжения.
- **`guard_read_tool` и таймаут:** сортировка тысячи элементов дешёвая, тяжёлых запросов в инструмент не добавлять.
- **Деплой:** пересоздание стирает логи контейнеров и сдвигает фазу тика на «старт плюс интервал». Ждать конец тика по `grep -F 'Incremental pipeline completed'`. `--force-recreate` (BUG-090), бот — под `--profile bot`, `--no-deps`, Postgres не трогать.
- **Два параллельных полных прогона** на одной `tg_parser_test` конфликтуют — PR standard по очереди.

## 5. Тесты (минимум)

- **MCP-инструмент:** тема с N элементами > порции — первая порция = порции по умолчанию, `items_count = N`, признак продолжения `true`; **повторный вызов строго по `pagination_pending`** проходит валидацию и даёт следующую порцию; последняя страница — остаток, признак `false`, без `pagination_pending`; смещение за пределом — `[]`; размер выше верхней границы урезается; бандла нет — `items=None`, `items_count=0`.
- **Сортировка:** якоря (`role == anchor`) первыми, затем `score` по убыванию (`None` = 0), равные — по `source_ref`; страницы не пересекаются и в сумме дают каждый элемент ровно один раз.
- **Контрактный тест пагинации** — по решению §3 п. 2: инструмент в реестре со своей фикстурой или явное исключение с комментарием.
- **Ресурс** `tgparser://topics/{topic_id}` — поведение по §3 п. 3 (`test_bug103_surface_batch.py`).
- **HTTP `/bundle`:** query-параметры, `total_items` полное, правило §3 п. 5; если принят §3 п. 4 — новая строка HTTP-матрицы (бандл без карточки при ограниченном scope) и `/bundle` для удалённого канала в HTTP-части матрицы BUG-107.
- **F4-B:** `test_f4b_*` зелёные; `workspace_id` не меняет `items_count`.
- **Бот:** существующие тесты зелёные (ответ не меняется, нового теста на внутренности не нужно).
- **Красный на `main`:** вызов **без новых аргументов** по теме больше порции возвращает не больше порции — на `main` падает (отдаёт всё). Проверить через `git stash` правок `tg_parser/`.
- **Полный PR standard** (`TEST_POSTGRES=1`, фиктивные ключи) зелёный.
