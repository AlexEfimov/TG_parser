## 2. Что меняется относительно черновика 2026-08-31

1. **Повестка сессии решения.** Черновик обосновывал B-слайс тем, что дефекты испортят сигнал только что запущенного потока 2. Сигнала нет: оба человека добавили канал и не вернулись. Вероятная причина — после `add_channel` бот ничего не присылает и возвращаться незачем, то есть это вопрос первого опыта, а не качества топикизации. Проверяется одним нейтральным вопросом (§3).
2. **Экономия от чистки удалённых каналов** — около четверти стоимости Phase 2, а не больше: остальное снимает только потолок контекста (BUG-108 b).
3. **Утверждение «у свежего канала ноль кросс-связей»** устарело: инкрементальные тики добрали 48. Сам дефект (полный прогон не линкует) остаётся — BUG-106.
4. **Предусловие «подтвердить баланс»** снято замером. Остаётся гигиена ключа (§4, этап 4).

## 5. Как получены факты

Всё — read-only: SQL в `BEGIN TRANSACTION READ ONLY … ROLLBACK` через `docker exec tg_parser_postgres psql`, Prometheus через `docker exec tg_parser_prometheus wget` (`increase(tg_parser_llm_tokens_total[21d])`, `query_range` по часам с шагом 3600), `docker logs` трёх контейнеров, один вызов прод-MCP `search_knowledge_base(mode=keyword)` от admin.

**Не проверено:** баланс и распределение расхода в Console (действие владельца); точная стоимость Phase 2 — оценка по list price и сумме всех Sonnet-токенов в часовых всплесках, без разделения prompt / completion; активность когорты вне бота и MCP. Пассивного канала ценности у них тоже нет: `digest_subscriptions` = 0 у обоих, создания watchlist в `audit_log` нет — то есть после `add_channel` продукт им ничего не присылает.
