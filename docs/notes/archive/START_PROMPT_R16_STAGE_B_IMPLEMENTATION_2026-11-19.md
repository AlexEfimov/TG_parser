## 3. Ловушки (сверх исходного §3)

- **Две K в одном файле.** `_compute_match_score` по умолчанию берёт `ASSIGN_KEYWORD_TOPK` (Phase 1, 3). Вызов supporting без явного `topk=` молча останется на K = 3. Тест на то, что Phase 1 на фикстуре даёт бит в бит прежний score, — обязателен.
- **При n ≤ 30 G — это `mean`.** Узкие темы теряют до 90 % supporting и больше (andre_dataist «Робототехника» 100 → 9; 5 тем пустеют полностью) — задуманный эффект, а не регрессия. Темы с n = 31–60 урезаются умеренно (aiinsideteam «Uber», n = 47: 100 → 45; 58 тем с n > 30 урезаны вдвое), темы с n ≫ 30 почти не меняются. Не «чинить» это в ревью.
- **Два масштаба score в бандлах после деплоя** — supporting по K = 30, Phase 1 (`incremental keyword assign`, 4a) по K = 3; см. точку решения §2 п. 6. Score не нормализовать молча; контракт допускает любой масштаб.
- **G действует не на тике.** Инкрементальный тик и сверка BUG-075 идут через Phase 1 и `add_items` (§1) — их решение 2a не меняет. Новая формула supporting работает при полном прогоне, слиянии, бандлах новых тем после discover и в пересборке.
- **Пересборка по прогнозу — сверка, а не цель.** Сверять по каналам с §10.7, а не только агрегатом (его определяет mediamedics — 40 % документов). Расхождение по каналу больше 10 % — стоп и разбор, не подгонка.
- **Новый прод-прогон скрипта симуляции** для G не нужен. Если всё же понадобится — условия CLAUDE.md «Скрипт на проде до GO» (новый SHA → новый круг ревью).
- **Длинные прод-запуски и сон Mac** (дважды теряли прогоны из-за обрыва SSH). `caffeinate` держать **отдельным процессом** (например, `caffeinate -i -t <сек>` в фоне отдельным вызовом), а прод-команду — в форме `ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=6 prod '…'`: так она целиком видна в карточке и подпадает под правило `ssh *`. mediamedics — самый тяжёлый канал (11.9 тыс. документов, 262 темы, пик RSS симуляции до 1.4 ГБ; у `tg_parser` в compose нет лимита памяти).

## 4. Тесты (исходный §4 плюс)

- **G, границы** (W — сумма весов хитов: strong 1.0, weak 0.3):
  - n = 40, один strong (1/30 = 0.033) — не supporting;
  - n = 10, один strong (1/10 = 0.1) — не supporting из-за `<=`; два strong (0.2) — supporting;
  - n > 30: W = 3.0 (три strong, 0.1) — не supporting; W = 3.1 (один strong + семь weak, 0.103) — supporting;
