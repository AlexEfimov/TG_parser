### Почему когорта не увеличивает 2A

Соблазн записать двух тестировщиков как «2 из 3 сигналов 2A» надо погасить сразу, иначе решение будет построено на подтасовке. Матрица §5 меряет **входящий** интерес; поток 2 §4 — это «2–3 external validators», то есть **инструмент программы**, который оператор обязан был запустить (риск R-5: «Solo bias — owner использует только сам, не приглашает validators»). Запуск инструмента — не результат измерения. Что когорта **правда** производит — это goal #1 §3: «Validated priority list — какие friction-points реальны». И его она произвела в первый же час (§3).

## 4. Вердикт по триггерам §7

| Триггер | Состояние |
|---|---|
| 1. 5+ сигналов одного типа | **Не выполнен** (0/0/0) |
| 2. 3–4 месяца с 2026-06-06 | **ВЫПОЛНЕН** — 2026-09-01 это ~3 месяца; это и есть повод сессии |
| 3. Hard pivot (owner inactive и no growth) | **Не выполнен** — рост ~5×, прод активен |
| 4. Внешний catalyst | **Не выполнен** — paying customer / взлёт MCP не наблюдаются |

Формулировка триггера 2 сама предписывает исход: «фиксируем *не нашли catalyst → continue dogfooding или pause*». **Pause исключается** ростом и активностью. Остаётся continue dogfooding — вопрос только в том, брать ли к нему B-слайс.

**Мелкое расхождение в датах, чтобы о нём не спорили в сессии.** От 2026-06-06 до 2026-09-01 — 2 месяца 26 дней, то есть нижняя граница «3–4 месяцев» из §7/§20. При этом плейсхолдер §11 подписан «4 months — hard exit», а обновления от 11 августа трижды называют дату **~2026-09-01**. Формально окно можно было бы тянуть до ~2026-10-06; намерение владельца в документах зафиксировано как 1 сентября. Предлагается держаться заявленной даты и заодно поправить подпись «4 months» в плейсхолдере.

### Черновик решения (готов к правке и вставке в `DECISION_POINT_2026-09-01.md`)

> **Решение (2026-09-01).**
>
> 1. **Forced Decision Point по §7 триггер 2 отработан.** Catalyst не найден: inbound-сигналы 2A/2B/2C = 0/0/0. Pause отвергнута — owner-active baseline вырос ~5.2× по документам и ~3.3× по темам против baseline §8.
> 2. **Трек: A (continue dogfooding) + узкий B-слайс.** Ярлык «Wave 3» в ROADMAP **не** вводится: это не product-контракт.
> 3. **Scope B-слайса — только то, что искажает сигнал только что запущенного потока 2**, в порядке приоритета:
>    - **B-1. Нормализация `t.me/…` и `https://t.me/…` до username.** Убирает фантомные `sources` и врущую квоту у корня. Независима от модели владения.
>    - **B-2. `get_owned_channel_ids` → фильтр `deleted_at IS NULL`.** Проверить потребителей (`allowed_channel_ids` в `resolvers.py` / `mcp_server.py`): нужен ли кому-то доступ к темам удалённого канала. Тест на расхождение «счётчик vs квота».
>    - **B-3. Потолок контекста Phase 2 discover.** Вариант выбрать из инцидента 2026-08-28 §«follow-ups» (top-K, title-only, бюджет токенов). Phase 3 linking **сохранить**. Плюс `stage`-лейбл на `tg_parser_llm_tokens_total`, иначе эффект не измерить.
> 4. **Явно НЕ входит:** модель владения / sharing, Wave E graph retrieval, F11 HTTP CRUD, webhook 2A, F1 Full, split `add_channel`/`update_channel`, Event B retention flip.
> 5. **Окно продлевается на 4–6 недель** с re-check ~2026-10-06 (или досрочно при взятии любого порога §8 §5). Основание: поток 2 впервые активен, и это первый период, где матрица может наполниться не гипотезами.
> 6. **Онбординг когорты дополняется одной строкой** до выхода B-1: просить `@username`, а не ссылку, и предупреждать, что канал в инстансе занимает первый добавивший. Уже отражено в [`TEST_ACCESS_MULTI_USER.md`](../runbooks/TEST_ACCESS_MULTI_USER.md) §1.
> 7. **Перед любым LLM-scope:** подтвердить пополнение баланса Anthropic и снятие другой программы с ключа (follow-up 3 инцидента 2026-08-28).

Если владелец предпочтёт чистое A — из черновика достаточно убрать пункт 3 и оставить §3 как записанный friction-лог; тогда B-слайс переезжает в следующее окно.

- ❌ **team sharing / multi-owner «на всякий случай»** — прямой запрет §9; порог 2C не взят.
- ❌ Web UI / OAuth.
- ❌ Именование «Wave 3» без product-контракта (choice C).
- ❌ Реопен F5-B Phase 1 (ADR-0016 Rejected) и смена `RESUMMARIZE_MAX_AGE_DAYS=21`.
- ❌ Flip Event B retention без owner GO + backup + dry-run.
- ❌ Агрессивный опрос валидаторов — §9 разрешает только observation.

## 8. Что перевело бы решение в C (пороги на продлённое окно)

Смысл продления — получить настоящие данные, а не ещё один цикл гипотез. Что считать за срабатывание:

| Наблюдение | Ось | Что делать |
|---|---|---|
| Тестировщик **сам просит** доступ к чужой / общей базе, или третий человек просит «пустите почитать» | **2C** — порог ≥1 strong ask | Открыть ADR по модели владения; это единственный законный вход в sharing |
| Кто-то ставит MCP **без приглашения** оператора (нашёл сам), либо появляются stars / внешние issues | **2A** — ≥3 | F11 HTTP CRUD и webhook перестают быть спекуляцией |
| Просьбы «а где посмотреть подробнее / веб» от подписчиков digest'а | **2B** — ≥3 | Иначе web не обсуждаем |
| Тестировщик жалуется на **качество ответов** на кросс-канальные вопросы | Wave E | Сейчас у Wave E сигнал слабый по его же prep-документу; жалоба даёт первое измерение |
| Валидаторы отваливаются молча | hard signal | Немедленный re-check: продукт не удержал первых внешних людей |
