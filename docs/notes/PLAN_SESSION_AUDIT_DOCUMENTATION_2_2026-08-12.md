### W1 — Truth-check против матрицы #1

Для каждой строки матрицы найти, что документация утверждает о той же возможности:

| Класс | Значение |
|---|---|
| `agrees` | docs совпадают с прогоном |
| `contradicts` | docs утверждают обратное прогону (обе стороны) |
| `silent` | возможность работает, но нигде не описана |
| `stale-status` | статус верен, метаданные (дата, версия, счётчики) разошлись |
| `no-reference` | **только** для 6 строк с вердиктом `not_run` в #1 — сравнивать не с чем |

`no-reference` введён честности ради: у `subscribe_*`, `backfill_watchlist`, `force_resummarize`, `trigger_*`, `set/reset_llm_config` прогона не было, и любой другой класс для них был бы выдумкой.

Где искать: `FUTURE_FEATURES` сводная таблица, `ROADMAP_KARPATHY_LIKE_LIVING_KB`, `USER_GUIDE`, `MCP_AGENT_GUIDE`, `docs/adr/`, профильный runbook, `README.md` в корне.

**Обе стороны обязательны.** Занижения встречаются не реже завышений; аудит, который ищет только «наврали, что готово», пропустит половину.

Свип битых ссылок — **тот же класс, что зафиксирован в BUG-090** (сгнивший указатель; сам BUG-090 про bind-mount, а его follow-up формулирует дефект как «два deploy-документа, противоречащих друг другу»):

```bash
rg -o '\]\(([^)]+\.md)\)' -r '$1' docs --glob '*.md' | sort -u | while IFS=: read -r src link; do
  d=$(dirname "$src"); [ -f "$d/$link" ] || echo "DEAD: $src -> $link"; done
```

**Прогон на `dbadc69`: 207 попаданий. Чинить все — нельзя (кап §6) и не нужно.** Разложить и работать только с живым слоем:

| Класс | Признак | На `dbadc69` | Что делать |
|---|---|---|---|
| В `archive/**` | источник исторический | **140** | сосчитать, не чинить |

| root-anchored (`/docs/…`) | путь от корня ФС | 5 | отдельный класс, все в archive |

Внутри живых 67 различать «неверная база» (цель существует, путь считан от корня репо) и «цель отсутствует». Второе опаснее.

Свип видит только ссылки на `.md`; ссылки на `.py` / `.yml` / `.json` в него не попадают — это известное ограничение, не чинить в этой сессии.
